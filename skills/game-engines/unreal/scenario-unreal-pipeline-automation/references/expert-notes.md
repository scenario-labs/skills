## The Interchange product manager (Oq6KbrqkGnw, Unreal Fest 2024, UE 5.4)

- Flow: translator makes read-only translated nodes; pipelines create or edit factory nodes; factories make assets [00:03:08], [00:22:40].
- Presets are team policy: copy the engine pipeline into the project, set default, visibility and lock per property, point the project stack at it [00:10:59] to [00:16:00].
- The dialog remembers the last settings per pipeline, "Reset Selected Pipeline" shows the preset's real defaults [00:13:48]; scripted imports use the pipeline defaults [00:39:28]. This is why the skill always passes the preset explicitly.
- Stack order is execution order; a tweak pipeline must sit below the one that creates the nodes [00:20:22].
- Filter by disabling factory nodes and follow Factory Dependencies to drop the materials and textures only that mesh needed [00:31:33], [00:32:39].
- Graph Inspector pipeline at the end while developing; forgetting it made it pop up during an automated import in the demo [00:28:18], [00:40:00].
- `AssetImportTask` already routes through Interchange for supported formats; direct calls use the Interchange Manager with override pipelines [00:37:11] to [00:38:19].
- Runtime import is limited (no Nanite build or collision generation at runtime in 5.4) [00:40:47].
- Consequence the doc spells out: reimport remembers the pipeline stack and options used (Interchange doc, Reimporting Assets). A preset edited later does not reach assets already imported; the skill versions the policy (`plan_imports(..., policy=)`) and reimports with the preset in `override_pipelines` [added rule from the doc fact].

## Jamie Dale and Aaron Carlisle, Epic (0guOMTiwmhk, Inside Unreal 2019, UE 4.22)

- Scripted imports take class-default options, "not the last run of the import": set every option that matters [01:26:38].
- The editor holds a write lock on loaded assets; a separately spawned import may not save them; remote execution into the running editor avoids it, and Epic used it from Maya [01:16:47] to [01:17:49].

- Missing function usually means a plugin not enabled [00:36:20]; returned arrays are `unreal.Array`, wrap in `list()` [00:42:17]; Developer Mode writes a stub `unreal.py` of about 10 MB for the exact plugin set [01:12:10].

## Andrew Fray (KuIWCzujtag, Inside Unreal, published 2026, recorded on 5.5)

- Measure mean time to resolve, not bug count [00:09:48]. Start with data validation, then a few smoke tests, actor tests only for the most fragile system [02:01:26].
- About 30 to 40 percent of bugs trace back to something an asset validator could catch; write one per real bug [00:35:40]. `CanValidateAsset` runs before the asset loads: keep it cheap so many validators stay affordable [00:31:47].
- Adopting mid-project: grind through existing errors or allow-list them so only new ones fail the build [00:36:59] to [00:38:07]. Build failures are thanks, not blame [00:40:17].
- Any error log fails an automation test; a smoke test needs a clean console and a 0.5 to 1 s settle [01:04:47], [01:03:07]. Follow each smoke failure with a fire test, usually a validator; fire tests should fail more often than smoke tests over time [01:17:11], [01:18:48].
- See each test fail for the right reason before fixing [01:46:04]; review AI-written tests ("put this in claude.md and code review what it produces") [02:02:02], [02:07:43].
- Blueprint validators were broken in 5.4 to 5.6 with a fix promised for 5.7 [00:27:43]: Python validators sidestep it [verify 5.8].
- Performance tests advisory, never pass or fail at 29.9 fps [01:29:38]; tier cadence push, build, weekend, parallelize long suites [01:31:46], [01:55:36]; push when you can watch for about an hour [01:56:41].

## Epic documentation (5.8 pages)

- **Data Validation:** two rule types (`IsDataValid`, `UEditorValidatorBase`); the commandlet runs C++ rules only by default; Python validators register with `AddValidator`; every path of `ValidateLoadedAsset` must call passes or fails; rules run on save by default. 5.8 cvar `DataValidation.ReportCookValidationStats` (on by default) reports each validator's duration during cook: the measured side of Fray's "keep CanValidateAsset cheap" (cross-source in the data validation note).
- **Automation and Gauntlet:** `-ExecCmds="Automation RunTest ...;Quit"`, `-ReportExportPath`; PythonAutomationTest discovers `test_*.py`; the editor does not tick during Python, use latent commands; expected errors, screenshots and image comparison; Gauntlet built-ins `UE.BootTest`, `UE.EditorAutomation`, `UE.TargetAutomation`, resume up to 3.
- **UAT:** BuildCookRun stages Build, Cook, Stage, Package, Deploy, Run (Package is its own stage: no `-package`, no packaged app); "do not hand-author long command lines": build a custom launch profile once and copy everything after `BuildCookRun` from the Output Log (`P.buildcookrun_diff` compares ours against it); `-CmdLineFile=` for long lists; cook on the fly needs `-filehostip`. Iteration: the cook commandlet alone (`-run=cook -targetplatform=Mac`) catches cook errors without packaging; `-cookincremental` (5.6, Beta in 5.8) cooks incrementally against Zen (version deltas).
- **Interchange:** option names (collision prefixes, Build Nanite, LOD groups, Material Import as instance with Parent Material, Detect Normal Map, Flip Green Channel, Vertex Color Import Option Replace, Ignore or Override); reimport remembers the stack; material reassignment on reimport conflicts removed; Python pipelines derive `InterchangePythonPipelineBase` (sample truncated). The pipeline digest's P2 preset sets Vertex Color Import Option to Ignore unless the master uses vertex color [added there].
- **Python:** 3.11.8, editor only; `-run=pythonscript` loads no level; `init_unreal.py` and Startup Scripts; never move assets with `os` or `shutil`; imports are not undoable. Headless the asset registry may still be scanning: `wait_for_completion()` before queries (5.8 batch example). Since 5.5 a script failure only logs an error unless `-ScriptErrorsAreFatal` (version deltas, Headless entry points): exit code 0 is not a verdict, the job's result line is (`P.job_verdict`).
- **Python API 5.8:** `destination_name` ignored under Interchange; `result` deprecated for `get_objects()`; `delete_asset` is a force delete that may clear undo; `load_level` closes the current level without saving; `create_asset(..., overwrite_existing)`; `InterchangeManager.import_asset` and `reimport_asset` return "Array[Object] or None" (saved API page, `sources/docs/automation-pipeline__python-api-reference-key-classes.md`). Not stated anywhere saved: whether assigning a static mesh LOD group regenerates LODs, and the LOD count per group, so the skill counts LODs after setting the group and builds an explicit chain when short; its class minimums (3 or 4) are [added] project defaults.
- **Unreal MCP:** loopback `127.0.0.1:8000/mcp`, no authentication, tool calls serial on the game thread, Python toolsets on `unreal.ToolsetDefinition`, `ModelContextProtocol.RefreshTools`.
- **macOS requirements:** Xcode 26.0 minimum, 26.1.1 recommended, 26.4 incompatible; Nanite and VSM on M2+ (Beta).
- **5.8 release notes:** Zen cooked output store default and `LimitProcessLifetime=false`; batch processor; PythonScript commandlet enables source control; SupportedClasses mandatory; Interchange dialog rework, uFBX, USD asset import production ready.
- **Datasmith:** scene then finalize; edit after import; `destroy_scene()`; Python 2 samples to fix.
