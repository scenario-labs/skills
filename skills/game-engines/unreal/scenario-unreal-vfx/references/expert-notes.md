## Adam Kiraly (Senior Technical Artist, Tanglewood Games): Optimizing Niagara, Unreal Fest Orlando 2025 (71c5yv-XeY8)

- Optimize the world, not the effect: reduce system ticks and instances across the level, usually late on signed-off content, without changing the look [00:00:35]-[00:01:07]; Effect Types are "the backbone" [00:14:14].
- `stat fps` and `stat unit` always on, "if those are not enabled all the time, you're doing it wrong" [00:04:07]; then `stat NiagaraOverview` (GT Concurrent Total, GT Total, RT Total), `stat Niagara` tags (CNC: emitter and particle count, sim complexity; GT: system count, activations, scalability and significance manager; RT: GPU dispatch, rendering, culling) (slide 00:05:41), `stat NiagaraSystems` with asset paths, `stat NiagaraEmitters` [00:06:18]-[00:07:24]; `stats.MaxPerGroup` unhides truncated rows (frame 00:05:25).
- GT Concurrent is worker time; the same 4 ms is harmless on 16 cores and deadly on 4; he profiles with affinity limited to 4 cores [00:04:41]-[00:05:15], slide 00:01:26.
- The RT pays a dispatch for every GPU simulation, visible or not [00:05:47]; find systems ticking with hidden renderers in the debugger's in-world view [00:08:48]; the FX Outliner shows owner, pooling state, culled or uninitialized [00:08:48]-[00:10:28].
- He spends 30 to 50 % of his time in Insights; no `statnamedevents`, no Niagara in the trace (`trace.file default,statnamedevents`, slide 00:11:23); search `NS_` timers [00:10:52]-[00:14:14]; Insights also catches cases where Niagara looks guilty but is not [00:11:58].
- Effect Type fields: Allow Culling for Local Players, Update Frequency (Spawn Only suits short effects), Cull Reaction (Kill, Kill and Clear, Asleep, Asleep and Clear, Pause), Significance Handler (Distance, Age), System Scalability Settings per quality (Max Distance stops ticking, not rendering, and the scalability manager pays for the check [00:16:57]; Max Effect Type and System Instances; Cull Proxy saves the tick, not the RT [00:18:02]; visibility culling), Emitter Scalability spawn multiplier [00:14:29]-[00:19:10].

## Xiao Yue (Technical Artist, Epic Games China; ex-film FX): Advanced Niagara Fluids, Unreal Fest Gold Coast 2024 (PikR41luBws)

- "There's no hidden code in Niagara fluids": every solver step is a module or stage you can open [00:14:16]; most gas effects only need a template and the Emitter Summary [00:13:29].
- Look comes from the source: shape noise on the source particles, not turbulence in the solver ("energy coming from nowhere") [00:10:40]-[00:11:14]; for dust: directional burst source (GPU), rename the source reader or nothing changes, temperature off, density buoyancy (points down) [00:11:49]-[00:12:23]; shadow casting noticeably improves fidelity [00:12:56].
- Cost knobs: Pressure Solve Iterations (6 loses swirls and water volume versus 10) and advection Interpolation Type (Cubic keeps detail, Linear cheaper); Vorticity Confinement restores swirl [00:16:32]-[00:20:33].
- Grids: Rasterization Grid for atomic min, max, add; Grid Collection reads and writes in one stage; half float for density and temperature [00:03:08]-[00:04:51]. Sim stages iterate data interfaces (Iteration Source), repeat with Num Iterations; separable blur inside a Sim Stage Loop (4 loops) [00:06:55], [00:28:24]-[00:29:11].
- A grid that follows the player moves in cell-size snaps so relocation copies rather than resamples [00:24:21].
- Collision: screen depth cheap but 2D; Global Distance Field 3D, low-res, no skeletal; Rigid Mesh Collision accurate, costly with many objects; her split: GDF for static world, Rigid Mesh filtered to characters [00:24:56]-[00:26:06].
- Wind is drag toward `Transient.AdvectionVelocity`, not force (blows up) or set velocity (flat) [00:29:33]-[00:31:18]; baked smoke sprites get lifetime from wind speed [00:31:54]; particle volume-domain rendering is what Heterogeneous Volumes fall back to on lower end [00:32:28]; Physics Fields are a CPU to GPU messenger shared by Chaos, cloth, Niagara and materials [00:26:40]-[00:28:24].

## Epic documentation (UE 5.8)

- **Niagara overview and Flipbook Baker:** Emitter Spawn and Update always run on the CPU, whatever the sim target (Emitters); prefer Dynamic Inputs and Micro Expressions over new modules; baker tiles are not rescaled: power-of-two texture and a dividing grid, 8 x 8 on 1024 = 128 px; baker fps equal to the 30 fps authoring rate; bake is premultiplied, divide RGB by A; Clear before a variation.
- **Scalability and best practices:** start with Effect Types on every system; system as a service for concentrated spawns; per-emitter overhead is fixed (VM), consolidate with spawn index and multiple renderers instead of Cascade-style emitter per element; GPU vs CPU: 1 GPU particle can cost the resources of 64, CPU for small counts or GPU-bound projects, validate by profiling; fixed bounds cheaper, except small effects traveling far; avoid warmup; mesh hygiene (no collision, no shadow, no distance field, no extra UVs); spread large bursts; Require Current Frame Data off when nothing moves; attribute reader over events; sorting costs.
- **Effect Types and budgets:** created at FX > Niagara Effect Type; Budget Scaling curves (distance, instance count, system instance count) and Max Global Budget Usage; Debug HUD console syntax (`fx.Niagara.Debug.Hud Enabled=1 OverviewEnabled=1 SystemDebugVerbosity=2 SystemFilter=*x* ShowGlobalBudgetInfo=1`), `fx.Niagara.Debug.PlaybackMode`, `PlaybackRate`, `fx.budget.enabled`, `fx.Budget.GameThread`, `GameThreadConcurrent`, `RenderThread`; FX Outliner capture with pooling state; Session Browser targets other devices.
- **Lightweight emitters and Data Channels:** 17 supported modules; pure stateless systems are the most performant; 20 x 20 stress test reading Game Thread Average, Frame and Draw; NDC listener needs Infinite loop plus Complete if Unused; payload types include Chaos destruction and Niagara collision events.
- **Fluids:** Beta, "use caution when shipping"; 2D gas for games and torches, 3D gas for hero or cinematic, bake otherwise; Pressure Relaxation near 1; Scale Emission by dt for frame-rate-independent sourcing; Render Temperature Black Body gives the physical fire ramp; Cinematic scalability plus MRQ game overrides.
- **Chaos destruction (Geometry Collections, Fields):** source meshes watertight and non-intersecting (open faces simulate worse and unpredictably, intersecting parts are pushed apart at start); avoid falloff with external strain for performance; disabled bodies never wake, sleeping ones wake on contact, Kill removes at once; quickstart thresholds 5000 / 500 / 50, strain 50000, radius 100.
- **Python API 5.8:** `NiagaraSystem`, `NiagaraComponent`, `NiagaraFunctionLibrary` expose system settings, User parameters, seek and advance, sim cache, `init_for_performance_baseline`, `allow_scalability`, pooling method at spawn; no emitter or module editing. `GeometryCollection` exposes damage, clustering, connection type, size-specific data, Nanite, root proxy, custom renderer, removal and Dataflow; not per-bone data; several properties are read-only attributes but read-write editor properties.
